# EUKARYOME with ONT: reference choice, preparation and classification

## 1. Marker identity comes first

EUKARYOME provides separate nuclear rRNA reference distributions. Use **SSU for 18S rRNA**, **ITS for ITS**, LSU for 28S, and LONG for an SSU–ITS–LSU operon. A read generated by a long-read sequencer does not automatically require the LONG reference set. An ITS1- or ITS2-only experiment also needs region-aware validation; a full ITS reference may contain more sequence than the query, which is acceptable when query coverage is evaluated correctly.

For the next ONT microbial-kit ITS project, use the ITS profile and the ITS reference set. Confirm the actual kit/amplicon with the laboratory record. The published SQK-MAB114.24 workflow includes separate 16S and ITS primer reactions and describes ITS primarily for fungal profiling. Plant assignments are retained by PaGleba, but the assay is not an unbiased survey of all eukaryotes.

Sources: [EUKARYOME downloads](https://eukaryome.org/mothur/), [ONT protocol](https://nanoporetech.com/document/microbial-amplicon-barcoding-sequencing-for-16s-and-its-sqk-mab114-24).

## 2. Versioned references, no silent “latest”

```bash
pagleba db eukaryome --marker ssu --version 2.1 --out /refs/eukaryome21_ssu --threads 12
pagleba db eukaryome --marker its --version 2.1 --out /refs/eukaryome21_its --threads 12
```

Each output directory is independent. The release is explicit; future releases may require checking the archive/rank schema. `--url` can point to an explicitly chosen official mirror/archive. `--sha256` verifies an externally trusted checksum when supplied. A locally calculated checksum alone establishes file identity, not independent publisher authenticity.

The EUKARYOME “mothur” format is used because it provides a paired FASTA and taxonomy file. The pipeline does not require running mothur. Nested ZIP/7z packaging is handled; archive changes cause an explicit error rather than guessing a mismatched taxonomy file.

Database names and ranks are retained from the chosen release. The software does **not** claim to have independently reconciled every eukaryotic name with current external nomenclature registries. Local path/feature hashes are not NCBI taxIDs.

## 3. Preparation checks and storage

Preparation performs:

1. Archive CRC/integrity checks where applicable and recording of the downloaded SHA256.
2. Parsing reference IDs and checking one-to-one FASTA/taxonomy compatibility. Duplicated/missing IDs are not silently discarded.
3. Uppercasing DNA, changing U to T and removing alignment gap characters `-` and `.`; the resulting IUPAC alphabet is validated.
4. Explicit domain addition for the EUKARYOME format. Special `_Bacteria` and `_Archaea` reference groups retain their proper domains; other EUKARYOME paths are eukaryotic.
5. SQLite reference taxonomy creation, keyed by reference ID. Full paths are available on demand instead of reparsing a large JSON dictionary per chunk.
6. Building a minimap2 index with the requested preset and a single index partition large enough for the supplied reference. Prepared data and index are hashed.
7. Writing `database.json` with provider, marker, version, sequence/base counts, schema, minimap2 version and hashes.

The positional EUKARYOME parser expects the documented kingdom→species levels, with a local domain prepended. It fails when a future file has an unexpected number of ranks. Use the explicit ranked TSV importer for a genuinely different schema instead of treating positions as known ranks.

The classifier verifies database files once per database per invocation, marker compatibility, minimap2 version and index preset. Repeated identical sequences with different reference IDs are retained: taxonomy ambiguity among such references is relevant to LCA.

Large ITS references can require appreciable RAM for indexing and mapping. SQLite reduces taxonomy-loading overhead; it does not eliminate minimap2 reference memory. Reference preparation and per-read QC disk costs should be included in the pilot/hardware plan.

## 4. ONT-specific parameters

The default preset is `map-ont`, preserving the original PaGleba alignment strategy. For sufficiently accurate contemporary ONT reads, minimap2 also offers `lr:hq`; select and validate it explicitly if appropriate:

```bash
pagleba db eukaryome --marker its --version 2.1 \
  --preset lr:hq --out /refs/eukaryome21_its_hq --threads 12
pagleba set --config /work/project/project.json --key markers.its.preset --value lr:hq
```

Index and mapping presets must agree. Do not reuse a `map-ont` index while claiming it was built with another preset. Record basecalling model/read accuracy in the study methods. There is no guarantee that one preset is optimal for every marker, read length or library.

Alignment uses base-level PAF (`-c`), `--secondary=yes`, `-N 50` by default, `-p 0.90`, and `-K 100M`. Candidate reporting limits are explicit in per-read output. All read occurrences have distinct generated QueryIDs even when original read UUIDs repeat. Original UUIDs remain available in `ReadID`; duplicates are not removed. Generated query identifiers are deterministic. Minimap2 tie-breaking can depend on query names, so changing sample/query identifiers or mapper versions can change some ambiguous near-best candidate sets; such changes are not advertised as bit-identical reproduction.

Optional `min_read_qscore` uses the read's mean error probability, converted back to a Phred score; it is not an arithmetic average of Phred characters. It is disabled unless explicitly configured. Length limits are explicit. Rejected technical records remain represented by status and source data.

Source: [official minimap2 documentation](https://github.com/lh3/minimap2).

## 5. Primers and the region actually mapped

Historical **18S F566–R1200** example, only when those primers were used and remain in the input:

- Forward 5′→3′: `CAGCAGCCGCGGTAATTCC`
- Reverse 5′→3′: `CCCGTGTTGAGTCAAATTAAGC`
- Linked forward orientation: `F...reverse_complement(R)`
- Linked reverse orientation: `R...reverse_complement(F)`
- Historical settings: error rate 0.15, overlap 16, both primers required, 400–1200 nt after trimming.

This is **not an ITS primer specification**. The ITS profile has no fabricated commercial primer pair. Supply the verified sequences or explicitly leave trimming disabled, documenting whether they were removed earlier. Do not perform a second trimming pass expecting primers already removed by the basecaller/laboratory.

In linked mode, Cutadapt saves untrimmed, too-short and too-long reads separately. Both input orientations are supported without changing read UUIDs. The scientific implication of requiring both primers must be evaluated in a pilot: degraded or partially sequenced amplicons can be lost.

Sources: [Cutadapt linked-adapter documentation](https://cutadapt.readthedocs.io/en/stable/guide.html), [18S primer study](https://doi.org/10.1371/journal.pone.0087624).

## 6. Accepted alignments and competing-hit LCA

Per-read settings are configurable. The original 18S study and initial ITS pilot template use:

- alignment identity ≥ 0.95;
- query coverage ≥ 0.80;
- accepted competing alignments with alignment score AS ≥ 0.99 × the best accepted AS;
- up to 50 reported secondary alignments.

Definitions:

- **Identity:** PAF matching bases divided by alignment block length.
- **Query coverage:** `(query_end − query_start) / query_length`.
- **Score window:** a fraction of the mapper's alignment score, not a taxonomic confidence probability.

LCA is taken across the ranked lineages of accepted near-best references. Species evidence is aggregated to genus or a higher common lineage; species is not automatically assigned. If plausible references disagree at genus, the row remains unresolved at that level. If a near-best score window reaches the candidate limit, genus is conservatively withheld.

A high score and one top reference do not establish taxonomic certainty. The candidate cap cannot prove that all plausible references were reported. Short or highly divergent ITS may map poorly despite biological presence. Truncation/candidate and unresolved statuses must be reviewed in the pilot.

**The 95% identity value is an operational pilot threshold, not a universal ITS genus/species boundary.** Validate it with the relevant assay, read quality and positive/mock controls. An overly strict threshold loses divergent reads; an overly permissive one creates unsupported assignments.

## 7. Every occurrence is accounted for

Each retained/prepared input occurrence receives exactly one classification/QC status: eukaryotic/bacterial/archaeal genus or unresolved genus, organelle, pseudogene, synthetic control, unresolved domain, no acceptable alignment, unaligned, length filtered or quality filtered.

The target table defaults to Eukaryota for EUKARYOME, and Bacteria for the bacterial profile. **All eukaryotic groups, including plants and algae, remain** unless an explicit project-level taxon exclusion is requested. Non-target and technical statuses are retained separately; they are not quietly forced into the target community denominator.

`taxonomy_all_domains_counts.tsv` retains classified non-target domains; `all_status_counts.tsv` retains the full status balance. Per-sample sums are checked against input occurrences. Optional downstream exclusion lists produce separate derivative tables while preserving the unfiltered target table and an exclusion audit.

Relative abundance is divided by all retained target-domain assignments in that sample; the denominator after an explicitly configured exclusion is reported separately. Unaligned reads are not redistributed to known taxa.

## 8. Checkpointing and reproducibility

Default chunk size: 5,000 occurrences. Each sample retains a streaming FASTQ iterator so completed chunks do not require rereading the entire sample from the beginning for each chunk. SQLite lookups are cached within a chunk. The pipeline still intentionally hashes unchanged inputs/databases at restart to detect accidental changes.

Each chunk contains compressed assignments, PAF alignments, exact mapper command, mapper log, QC counts and an atomic `COMPLETE.json` with SHA256 values. Completion is recorded only after gzip streams are read to EOF/CRC validation. Ctrl+C terminates the active minimap2 process group. An interrupted chunk is repeated; completed verified chunks are reused.

Changing input sequence data, database contents, minimap2 version, marker, chunk layout or scientific thresholds requires a new output definition. Never delete a configuration file merely to make incompatible checkpoints appear reusable.

## 9. SILVA and custom references

For a matching SILVA export:

```bash
pagleba db prepare --provider silva --marker 16s --version 144 \
  --format silva \
  --fasta /refs/download/SILVA_144_SSURef_NR99_tax_silva_trunc.fasta.gz \
  --taxonomy /refs/download/taxmap_slv_ssu_ref_nr_144.txt.gz \
  --rank-map /refs/download/tax_slv_ssu_144.txt.gz \
  --out /refs/silva144_16s --threads 12
```

The SILVA importer uses the rank map rather than assuming every taxonomic path has the same number of positions. Surplus taxmap entries not present in the selected FASTA are explicitly counted and excluded from the prepared index taxonomy; all FASTA IDs must still map exactly once. Obtain matching exports and comply with their license. The pipeline does not download or reconcile SILVA names automatically to “latest” LPSN.

Custom ranked taxonomy TSV:

```text
reference	Domain	Kingdom	Phylum	Class	Order	Family	Genus	Species
refA	Eukaryota	Fungi	Ascomycota	...
```

Use `--format tsv`, explicit provider/marker/version and the complete matching FASTA. A marker label is a provenance declaration checked by the program, not a substitute for checking the biological content of user-supplied references.

## 10. Known methodological boundaries

No dedicated chimera detector, ASV denoiser, OTU sequence clustering, species consensus/assembly, contamination model or absolute biomass calibration is silently run. Coverage/LCA disagreement is not equivalent to PCR-chimera detection. If those steps are added externally, retain their parameters, rejects and count balances and enter the verified processed FASTQ into the manifest.

EUKARYOME provides [reference-based chimera resources](https://eukaryome.org/uchime/), but region/read-error compatibility and validation matter. ITS and 18S tables are different assays; do not concatenate their read counts as interchangeable observations. Cross-domain models use distinct blocks and acknowledge taxonomy-derived functional dependence.

Reference database: [EUKARYOME publication](https://doi.org/10.1093/database/baae043). Database licensing and method/tool citations remain the operator's responsibility.
